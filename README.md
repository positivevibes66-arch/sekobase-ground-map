# SEKOBASE 地盤ベースマップ

- `index.html` — 地盤ベースマップ（ボーリング柱状図 / J-SHIS メッシュ）
- `pile.html` — **杭計測**：羽根付き鋼管杭・回転圧入の傾斜／偏芯をスマホで計測する

---

## pile.html — 杭の傾斜・偏芯計測

打設中の杭の傾斜をスマートフォンのカメラで計測し、偏芯の実測値と組み合わせて
**設計杭頭レベル（地中）での偏芯**を求める。外部機材は不要。

### 計測の原理

スマホを鉛直に構える（＝光軸を水平にする）と画像面が鉛直になり、
**世界の鉛直線は画面上でも必ず鉛直線に写る**（透視投影の性質）。
したがって画面上で「重力から求めた真の鉛直方向」と「杭のエッジ」がなす角が、
そのまま実際の傾斜（撮影方向に直交する成分）になる。
直交する2視点から測れば傾斜ベクトルが決まる。

- **方位磁石を使わない。** 鉛直の基準は重力のみなので、鋼管杭の近傍でも磁気の影響を受けない。
- **カメラのロール（傾け持ち）は補正される。** 重力ベクトルを基準線にしているため。
- **回転を止める必要がない。** 円筒のシルエットは回転しても変わらない。
  むしろ首振り（偏心回転）が疑われる場合は複数回撮って平均する方が正確。

### 連続計測（既定）とその理由

回転圧入では杭が首を振る（偏心回転する）ことがあり、**静止画1枚では振れのピークを
掴んでしまう**。1回転分を通して平均すれば首振り成分が消え、回転軸そのものの傾斜が残る。

そのため既定は **連続計測**：ガイド線を杭の左右の縁に合わせて開始すると、
指定秒数のあいだ毎フレームを解析し、平均・ばらつき(1σ)・時系列を記録する。

**動画ファイルは作らない。** `MediaRecorder` で録画すると、フレームのタイムスタンプと
センサー値を後から突き合わせる必要があり、ブラウザでは信頼できる同期が取れないため。
代わりに `requestVideoFrameCallback` でライブのフレームを1枚ずつ取り出し、
その場で「そのフレームの重力ベクトル」と対にして解析する。
操作性は動画と同じまま、同期の問題が消える。

- エッジは**輝度勾配のピークを放物線フィットでサブピクセル**まで求める。
  走査線ごとに候補を複数残し、**RANSAC で最も多くの走査線が乗る1本の直線**を選ぶ
  （文字や陰影など、輪郭と紛らわしい線に引きずられないため）。
- 走査する縦方向の範囲は、指定された4点の上下端から決まる。
- 初回フレームで杭が背景より暗いか明るいかを判定し、エッジの極性を決める。
- ピッチが許容外のフレーム、追跡に失敗したフレームは自動で除外される。
- 検出できない場合は**誤答せず棄却**する（`test/edge-tracking.test.js` で確認）。
- 傾斜の時系列がそのまま**首振りの波形**として残る。

### 動画ファイルからの計測（据置きカメラ）

各視点の「動画」ボタンから、ネットワークカメラ等で撮った映像を読み込んで解析できる。

固定カメラには IMU が無いが、**カメラが動かないので鉛直の基準はクリップ全体で1回
決めれば足りる**。下げ振り・水準器で立てたポール・建物の柱など鉛直と分かる物を
画角に入れておき、その1本を2点で指定する（水平に据えたことが確かなら画像の鉛直をそのまま使う）。

手順は ① 鉛直基準 → ② 杭のエッジ（追跡の初期値）→ ③ 解析。
解析速度は 1〜8倍から選ぶ。早送りするとブラウザがフレームを落として採用点数が減るが、
落ち方はランダムなので平均は歪まない（`test/video-e2e.test.js` で確認）。

> **1台しか据えられない場合**、得られるのは**視線に直交する1成分だけ**で、合成傾斜は求まらない。
> 単眼である限りこれは原理的な限界で、回避策はない（奥行き方向の傾きは単眼では精度が出ない）。
> したがって据置き1台は**トレンド監視**（ズレ始めの検知）に使い、
> **2軸の確定値はスマホの直交2視点**で取る、という分担になる。
> カメラは通り芯に平行に据えると、測れる成分が偏芯の実測と同じ座標系になる。

### 実映像で分かったこと

実際の打設映像（羽根付き鋼管杭 φ318.5×10.3 STK490 / 回転圧入 / 4K・24fps・手持ち）で
検証した結果、合成データでは見えなかった破綻が3つ出た。いずれも修正済み。

**① 走査範囲を画面比で固定していた** — 実際の杭は画面の上半分にしか写っておらず、
下半分では地面のテクスチャを追いに行って **116フレーム中0フレーム**しか通らなかった。
指定した4点の上下端から走査範囲を決めるようにして解決。

**② 走査線ごとに独立して「最も強い勾配」を選んでいた** — 杭に書かれた製品表示の白文字や、
円筒の陰影が作る輪郭と平行な線のほうが強く、そちらを掴んで直線に乗らなかった
（検出自体は毎フレーム11/11成功しているのに残差が中央値2.8〜7.1px）。
候補を残したまま **RANSAC で「最も多くの走査線が乗る1本」を選ぶ**方式に変更。
残差 1.05px → **0.42px**。

**③ 左右両方のエッジが揃うことを条件にしていた** — 杭の片側が重機のリーダーに重なると
その側の輪郭は候補にすら挙がらず、良く写っている側まで巻き添えで捨てていた。
角度を測るのに必要なのは軸に平行な直線が1本あることだけなので、
**通ったほうを使う**（両方通れば平均し、食い違いが大きければ棄却）。

修正後の追跡率は、画角が落ち着いている区間で **65%**、カメラが寄っていく区間で 7%。

> **計測中はカメラを動かさないこと。** 歩く・寄る・ズームすると杭の見かけの幅と位置が
> 変わって追跡が外れる。上の 7% はまさにその区間。
> また**動画ファイルには毎フレームの重力が無い**ので、手持ち映像ではカメラ自身の回転
> （上の映像では4.8秒で約1.9°）が杭の傾きと区別できない。
> 動画ファイルからの計測は据置きカメラ向けで、手持ちならライブの連続計測（IMUあり）を使う。

### 精度と制約

| 項目 | 値 |
|---|---|
| 単発（1枚）の再現性 | 画像ノイズ ±10階調で 1σ=0.008°、±35階調でも 1σ=0.030° |
| 連続計測 | 誤差は系統的な偏りを持たない（40枚平均の偏り ≦0.007°）ため、平均で落ちる |
| 首振りの影響 | 振幅±0.25°の首振りに対し、単発は最悪0.25°ずれる。60フレーム平均で0.001°以下 |
| 追跡できる傾斜 | 1/7（8°）まで復元を確認。許容超過の杭でこそ失敗しないこと |
| 撮影ピッチ許容 | 既定 ±1.0°（超えるとシャッターが切れない） |
| 遠近誤差 | 杭を画面中央±15%に収めれば 0.1° 未満（`test/measure-math.test.js` で検証済み） |

- 杭全体を画面に入れる必要はない。まっすぐな一部分が長く写っていれば十分。
  上に向けて撮ると鉛直線が収束して誤差が出る。
- **縦持ち専用。** 横向きにすると画像座標と端末座標の対応が崩れる。
- カメラとセンサーの利用には **HTTPS** が必要（GitHub Pages 可）。

### 計測ステップ

`建込み` → `圧入中` → `溶接前` → `溶接後` → `最終`

- **溶接前後**の傾斜ベクトルの差から、**継手の折れ角**が算出される。
  下杭が真っ直ぐでも継手で折れれば先端は大きくずれ、段数分だけ累積する。
- **最終**ステップで偏芯の実測値（逃げ杭・通り芯からのズレ）を、
  傾斜と同じ2方向・同じ符号（その視点から見て右が＋）で入力する。

### 設計杭頭レベルへの外挿

```
e_head = e_meas − t × Δh          Δh = 偏芯計測高さ(GL+) + 設計杭頭深さ(GL−)
```

杭軸は上へ行くほど +t だけ水平にずれるため、下がる分の符号は負になる。

判定は `合成偏芯 ≦ min(D/4, 上限値)`（上限の既定は 100mm、設定で変更可）。

> **前提** 外挿は杭が直線であることを仮定している。地中での偏向（玉石・支持層の傾斜など）は
> 地上からは判定できない。ヤットコ使用時は「ヤットコと杭が同軸」という前提で扱われ、
> その旨が判定結果に明示される。

### 検証

```
node test/measure-math.test.js     # 幾何の数式
node test/edge-tracking.test.js    # エッジ追跡
node test/video-e2e.test.js        # 動画解析（要 npm i playwright-core、無ければスキップ）
```

前2つは `pile.html` から該当部分を取り出して実行するので、式が二重管理にならない。

**`measure-math`** — 既知の傾斜を持つ杭を既知の姿勢のカメラで透視投影した合成データで、
重力ベクトルの導出、カメラロールに対する不変性、2視点合成、遠近誤差の上限、
外挿の符号、継手折れ角、許容値を確認する。

**`edge-tracking`** — 既知の傾きの杭の合成画像（ぼけ・ノイズ入り）で、
サブピクセルのエッジ検出と直線フィットを確認する。
明暗どちらの背景でも、カメラを傾け持ちしても、ガイド線が40pxずれていても復元でき、
コントラスト不足のときは誤答せず棄却すること、
そして首振りが連続計測の平均で消えることを検証する。

**`video-e2e`** — 合成した杭の映像をブラウザ内で canvas → MediaRecorder で作り
（VP8圧縮を通すので実際のカメラ映像に近い劣化が入る）、
ファイル選択 → エッジ指定 → 解析 → 保存 という実際の操作経路をそのまま辿る。
640×480・圧縮あり・首振り振幅±0.3° の条件で、真値0.42° を誤差0.03° 以内で復元することを確認する。
